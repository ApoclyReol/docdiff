# v1.5.0 — Review workflow, correctness fixes, Word tracked changes

This release is mostly about getting the comparison right and making the review itself simple. Independent reviews and two rounds of adversarial testing (about 32,000 random comparisons and 2,900 randomised UI steps) found cases where Doc Diff could hide or misstate a change or lose an edit; those are fixed and covered by tests.

## Review changes

- **Accept or reject each change**, as in Word: accepting keeps the new wording, rejecting restores the old wording of that paragraph. Both mark the change as reviewed, move on to the next open change, and can be undone. The change list shows how many changes are still open.
- **Calmer comparison view:** one top bar (files, previous/next change, search, view, export, more) instead of five bars and a floating dock. The change list is the only place with counts.
- **Overview bar** next to the text shows where the changes are and where you are; click or drag to jump.
- **Find in document** with highlighted matches and previous/next.
- **Larger, clearer text**, consistent colours (red removed, green added, a side bar for changed paragraphs, blue only for actions) and AAA text contrast in light and dark mode.

## Correctness

- **Changes near the page margin were hidden.** The header/footer filter treated any line close to the top or bottom of a PDF page as a running header. It now hides a line only if it repeats on at least half of the pages, and only where both versions contain exactly the same line. Any header or footer line without an identical counterpart is shown and compared. Pure page numbers ("Seite 3 von 9") stay hidden.
- **The word diff could alter the text.** For example "Frist 14 Tage" → "Frist 7 14 Tage" showed the old version as "Frist  Tage". Every row is now checked: unchanged + removed text reproduces the old version exactly, unchanged + added text the new one.
- **Bare page-number shapes were always hidden.** A table cell changing from "2/3" to "1/3" was invisible.
- **DOCX soft line breaks glued words together** ("Hauptstraße 1" + break + "12345 Berlin" became "Hauptstraße 112345 Berlin").
- **Invisible differences showed up as changes:** decomposed umlauts (NFD), soft hyphens, zero-width spaces, ligatures such as "ﬁ", narrow spaces, CR line ends. Text is normalised (NFC) before comparing; visible characters such as "m²" are never folded.
- **Renumbering no longer marks every following clause as changed.** Marker-only changes are shown in a muted style and not counted. Paragraphs that moved unchanged are labelled "Moved".
- **PDF intake:** hyphenated line breaks are joined, word spaces are derived from glyph positions, and wrapped lines starting with an amount or date stay in their paragraph.
- **DOCX numbering** is read from the document's own numbering definitions instead of being invented. Where it cannot be determined reliably, no number is shown.
- **Paragraph similarity** no longer counts repeated words several times.
- **Undo** no longer brings back text from a previously loaded document.
- **Editing one paragraph** could rebuild the new version incorrectly (header/footer lines moved, extra changes reported) and, on long documents, a quick second edit could drop the first. Both fixed.
- **Editing a heading** no longer re-pairs neighbouring paragraphs or turns the heading into a deletion plus an insertion. Ordinary PDF sentences starting with "§ 2" are no longer shown as headings.
- **Very long paragraphs** no longer hang the comparison.
- **Race conditions:** a slow file read can no longer overwrite a newer file chosen for the same side, and clearing a side cancels pending reads.
- **Ctrl/Cmd+C copies again.** Single-key shortcuts no longer fire with modifier keys, in text fields, or while a dialog is open.
- **Exporting before both files were loaded replaced your document with the sample.** The export menu is now disabled until a comparison exists.

## File handling

- Scanned PDFs, images, legacy `.doc`, `.rtf` and other unsupported files are rejected with a clear message instead of being compared as garbage. Partly scanned PDFs show which pages have no text.
- Password-protected and damaged files get a clear message.
- `.html` is read as text (scripts never run). Windows-1252 text and UTF-16 without BOM are read.
- A DOCX that contains tracked changes shows a warning, because it is compared as if all changes were accepted.

## Export

- **Word (`.docx`) with tracked changes.** Every open difference is a real Word revision (author "Doc Diff"), so you can accept or reject it in Word or LibreOffice; changes you already accepted in Doc Diff are applied, rejected ones are reverted. This replaces the previous HTML file with a `.doc` extension.
- **HTML report:** self-contained and read-only, with summary counts, a linked change list, the full redline, and a strict Content Security Policy.
- **Markdown:** document text is escaped, and changes render correctly in CommonMark.
- **PDF / print:** a dedicated print layout for all three views, with file names, date, page numbers and marks that survive greyscale printing.
- File names combine both document names and are safe on Windows, macOS and Linux.

## Not losing work

- The browser asks before you leave the page with unsaved edits; the app asks before actions that would discard them.
- **Saved work:** save both documents, your edits, the review status and the view as a `.docdiff` file and open it again later. Nothing is stored in the browser; the file is wherever you save it.

## Speed

- Comparisons run in a Web Worker, so the page stays responsive. 2,000 paragraphs: about 0.5 s instead of 5 s with a frozen page. PDF.js now runs in a real worker too.
- Navigation, search and view switching only update what changed.
- The start page appears about 3× sooner on slow connections (scripts load after the visible content).

## Interface and accessibility

- The start page explains the tool: what it does, what it cannot do, how the privacy protection works, and an FAQ.
- Plain labels throughout: "Alte / Neue Fassung", "Nebeneinander / Untereinander", "Annehmen / Ablehnen".
- WCAG 2.2 AA with no axe violations in the tested states, AAA text contrast, keyboard operation of every task, screen-reader announcements for each step and review decision, and `prefers-reduced-motion` support.
- English page at [docdiff.app/en/](https://docdiff.app/en/); the offline file follows the browser language.

## Security

- PDF.js runs with `isEvalSupported: false` (CVE-2024-4367 hardening in addition to the CSP).
- The documentation quotes the shipped Content Security Policy verbatim, and the build fails if they drift.

## For contributors

- The source is split into `src/template.html`, `src/styles.css` and `src/js/*.js`. The build still produces one self-contained HTML file.
- `node scripts/check.mjs` runs unit tests for the diff core, the export builders and the comparison worker, plus the privacy and build invariants.
